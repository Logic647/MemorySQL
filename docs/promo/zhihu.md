## 正文

## "你是谁?我们之前聊过吗?"

一个逐渐成为日常的场景:昨天让 Codex 把一个模块改了一半,今天想换 ZCode 接手——新开的会话里,agent 对你、对项目一无所知。你把背景从头讲一遍,它客客气气回一句"好的,我了解了"。讲的人累,听的人也未必真"了解":**上下文在每次换会话、换工具时归零**。

更别提会话历史本身的碎片化。我现在同时跑着三四个 AI 编码 agent,它们的聊天记录各存各的:`~/.codex/sessions`、`~/.claude/projects`、各家桌面版的私有数据库……格式互不相同,藏得还越来越深。想翻"上个月那次关于 WebSocket 重连的讨论",基本等于大海捞针。

这两件事其实是同一个问题:**AI agent 的记忆,到底该谁来管、存在哪?**

## 目前的几种答案,以及它们的取舍

**① 厂商各自的"记忆"功能。** 每家都推出了自己的记忆:Claude 的 memory、ChatGPT 的 memory、各家 agent 的项目指令文件。问题是**绑定生态**——厂商 A 的记忆喂不给厂商 B,而现实中我们恰恰是多家混用的。

**② 云端记忆服务(mem0、OpenMemory 这类)。** 跨工具、可移植,是正解的方向。但要接受的是:**你的完整对话史和画像要出本机**,存到第三方服务器。对"代码里全是商业逻辑、配置里全是密钥"的开发者来说,这个口子开不开,值得掂量。

**③ 厂商文件 + 手工整理。** AGENTS.md / CLAUDE.md 手写维护,可控但费劲,而且只有"你写进去的",没有会话里实际发生的。

我是开发者,自然想到第 ④ 条路:**数据留本机,自己造一个记忆层**。于是有了这个开源项目 **MemorySQL**(MIT)。

## 我的做法:捕获 → 存储 → 喂回

**捕获**:12 家 agent(Codex、ZCode、Claude Code、Hermes、Gemini CLI、Cursor、OpenCode、Qwen Code、Kimi CLI、CodeBuddy、WorkBuddy、Qoder)各写一个适配插件,监听它们本地的会话文件,增量入库。原始文件只读不改,`.env`、密钥文件一律跳过。桌面端有两家实在抓不到(Trae CN 本地加密、通义灵码纯云端),留了"粘贴文本导入"兜底。

**存储**:就是 SQLite,一个文件,在你机器上。检索两条腿:FTS5 全文(中文 trigram,不用分词器)+ sqlite-vec 向量(本地 ONNX 模型 bge-small-zh,不联网)。后者是为"字面搜不到"的场景准备的:搜"换机器了数据怎么办"能命中标题写着"迁移"的会话。

**喂回**:项目起了个 MCP server。MCP 这两年从 Anthropic 的协议变成事实标准,各家 agent 基本都支持了——它就是"AI 的 USB 接口",做一次 server,所有支持协议的 agent 通吃。任何 agent 连上后,新会话说一句「续接 MemorySQL」,调一次 `memory_get_context`,拿回:你的画像、相关记忆、项目状态、最近会话列表、**上一个 agent 干到哪的交接摘要**。它不用你复述,直接接着干。

〔图:01-context-handoff —— agent 终端里的续接包实况〕

写入侧有个设计我比较喜欢:`memory_log_progress` 让 agent 收工时结构化汇报"做了什么/下一步/卡在哪",但产出是**候选记忆,人工确认才转正**。agent 不能往你的长期记忆里塞东西,这是人和 agent 的权限边界。

## 几个刻意的取舍

**"本地明文"是选择,不是简陋。** 有人问过:不加密吗?我的答案:本机是你自己的地盘,信任边界应该画在"出口"——所以入库不脱敏(否则自己查自己都不方便),但任何导出/分享路径强制过脱敏模块。本地端点绑 `127.0.0.1` 无鉴权,这个信任假设我写在 `PRIVACY.md` 里讲得明明白白,不藏着。

**LLM 永远是可选项。** 摘要、冲突检测可以挂 LLM,但拔掉 LLM 整个系统照常用规则降级跑。语义检索从来就是本地模型。"AI 功能"不该是"必须持续付费调 API"的同义词。

**砍功能比加功能痛快。** 上周我把「笔记」和「知识图谱」两个功能整个下线了——自用了俩月,实用性撑不起它们的存在,连依赖一起删,前端产物缩了 75%。开源项目容易患上"功能囤积癖",敢删才是对自己诚实。

## 现状与边界

说实话的部分:这是个**自用驱动**的项目,装机用户目前不多;12 家适配器里,我自己日常真跑的只有四五家,其余是按各家存储格式调研 + 合成样本测试覆盖的,稳定性靠持续的"上游漂移监控"(每日黑盒检查各家 agent 有没有改存储格式)兜底。macOS 包还没签名,首次启动要右键确认。

支持 Windows / macOS / Linux,`winget install Logic647.MemorySQL`(收录审核中)或 GitHub Releases 直接下。

项目地址:https://github.com/Logic647/MemorySQL

## 回到最初的问题

"AI agent 的记忆该存在哪"——我的答案是:**存在你能删掉的地方**。跨工具互通靠 MCP 这种开放协议,不靠任何一家厂商的善意;数据留在本机,哪天不想用了,删一个文件夹就干干净净。
