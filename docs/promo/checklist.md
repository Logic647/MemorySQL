## 评论区 Q&A 预案(高频问题)

**「和 mem0 / OpenMemory 什么区别?」**
> 它们是给单个 agent 挂的记忆层/API;MemorySQL 先把 10 家 agent 的会话自动捕获入库,再通过本机 MCP 让任意 agent 续接——差异在「跨 agent + 自动捕获 + 交接闭环」,而且数据 100% 在本机。

**「Claude Code 自己有 memory / CLAUDE.md,够用了」**
> 那只在 Claude 内部生效。你换 Codex、换 Cursor,记忆带不走;跨 agent 目前没有原生方案,这就是这个项目存在的原因。

**「明文存储安全吗?」**
> 本机明文是刻意的(和 Obsidian 同一哲学):你的地盘你说了算,避免"加密=丢钥匙"的灾难;真正的边界在出口——所有导出/分享路径强制过脱敏模块。全盘加密可以用 BitLocker 做,那是操作系统的职责。

**「为什么 Windows 优先?」**
> 我自己的主力机是 Windows,先把每天真实在用的场景打磨好;macOS/Linux 源码可跑,安装包按需求排期。

**「会不会弃坑?」**
> v0.5.0 之前我已经迭代了 8 个里程碑(见 DEVLOG),工具是我自己每天在用的,后续至少有:更多 agent 适配、增量同步、macOS 安装包。(有真实路线图,别画大饼)

**「隐私问题:你们会拿我的会话数据吗?」**
> 没有任何遥测,数据不出机器;应用联网的只有你配置的 LLM API 和 GitHub 版本更新检查,全部可以在源码里审计。
