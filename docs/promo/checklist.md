## 评论区 Q&A 预案(高频问题)

**「和 mem0 / OpenMemory 什么区别?」**
> 它们是给单个 agent 挂的记忆层/API;MemorySQL 先把 12 家 agent 的会话自动捕获入库,再通过本机 MCP 让任意 agent 续接——差异在「跨 agent + 自动捕获 + 交接闭环」,而且数据 100% 在本机。

**「Claude Code 自己有 memory / CLAUDE.md,够用了」**
> 那只在 Claude 内部生效。你换 Codex、换 Cursor,记忆带不走;跨 agent 目前没有原生方案,这就是这个项目存在的原因。

**「明文存储安全吗?」**
> 本机明文是刻意的(和 Obsidian 同一哲学):你的地盘你说了算,避免"加密=丢钥匙"的灾难;真正的边界在出口——所有导出/分享路径强制过脱敏模块。全盘加密可以用 BitLocker 做,那是操作系统的职责。

**「三个平台都能用吗?」**
> 能,Windows / macOS / Linux 安装包都有。唯一要说在前面的是 **macOS 包未签名**,首次启动 Gatekeeper 会拦,「右键 → 打开」确认一次即可(或 `xattr -dr com.apple.quarantine /Applications/MemorySQL.app`)。

**「会不会弃坑?」**
> 已迭代 M0–M8 + 8 个发版(0.4.1 → 0.6.0,见 DEVLOG),工具自己每天在用。上个版本还砍了两个功能(笔记/图谱)——敢做减法说明还在真用。路线图:macOS 签名公证、增量同步、更多 agent。

**「隐私问题:你们会拿我的会话数据吗?」**
> 没有任何遥测,数据不出机器;联网的只有你配置的 LLM API 和 GitHub 版本更新检查,全部可在源码审计。注意一点:本地 MCP 端点只绑 `127.0.0.1` 且无鉴权,完整信任模型见 PRIVACY.md——我们把这写在明面上而不是藏着。
