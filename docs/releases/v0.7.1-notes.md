# MemorySQL v0.7.1 更新日志(2026-10-26)

> 这是一版**修 bug + 加一家适配**的更新。核心是两件事:新增 **DeepSeek Harness(dsh)** 捕获,以及修掉 v0.7.0 项目总结里几处「测试全绿但真机错」的问题。

---

## 本次更新内容

### 1. 新增 DeepSeek Harness(dsh)会话捕获(捕获矩阵 12 → 13 家)

DeepSeek 官方 agent 框架 [`deepseek-ai/deepseek-harness`](https://github.com/deepseek-ai/deepseek-harness)(命令 `dsh`,MIT),本地会话自动入库。

- 会话位置:`~/.dsh/sessions`(`DSH_HOME` 可覆盖),每会话一个 `session.vN.jsonl[.zstd]`
- 默认 zstd 压缩、且是「一次追加一帧」的**拼接帧**格式 —— 已正确解出全部帧(不是只解第一帧)
- 上游保留多代历史日志并存,采集按「代数最高」只读最新那份
- 子 agent 碎片会话(`delegationDepth > 0`)自动跳过
- 连接向导支持一键写入 MCP 配置(`~/.dsh/cordis.patch.yml` 的 cordis 补丁条目)

### 2. 项目总结:修掉三个真机才暴露的问题

- **总结越滚越小**:档位原本按「本批会话数」选,却截断「累计全文」——23 个会话的项目消化两轮后,总结从 4000 字被截到 800 字且**永远回不去**。现在按**累计规模**选档,且**只升不降**。
- **总结串到别的项目**:关键词匹配原本是「项目名或路径包含」,导致「桌面」这种词命中 24 个互不相关的项目(它们只是都放在 `H:\桌面\` 下),于是标题写着 A、总结正文却是 B 的结论。现在改为**项目名优先、路径仅兜底**,四处口径统一。
- **按会话分类显示 `#0`**:模型返回 `"#42"` 这类带修饰的 id 时被解析成 0。已修正。

### 3. `memory_get_session` 截断方向修正

输出超预算时过去保留的是**最旧**的消息(与文案「取最后若干条」相反),7000+ 条的长会话读不到最新进展。现在从最新往回填,提示语也改为「保留了**最近** N 条」。

### 4. 上游漂移检查不再对健康安装误报

dsh 的子 agent 会话与空会话「解析不出会话」是正常状态,旧检查器会判成格式漂移(🟰 触发一次白跑的适配发版)。现在区分「按设计跳过」与「真的读不懂」,并会尝试多个样本文件而不是只看第一个。

### 5. 其他

- `memory_search` / `memory_get_project_digest` 跟随同名项目合并口径
- 项目总结的 maxTokens 上调并按上限约束「按会话」条目数,避免输出被截断后整份作废回退规则模式
- 规则模式总结不再把会话清单重复打印两遍
- 数据库里手工编辑坏的总结行不再让 `memory_get_context` 直接报错,改为降级显示
