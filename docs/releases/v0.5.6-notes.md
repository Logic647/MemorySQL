# v0.5.6

> 这一版的重点不是加功能,而是**把几处"坏了但没人知道"的静默失效变成可见的**。

## macOS 首次支持(Apple Silicon / arm64)

三个平台里最新的是 macOS,这一版开始提供 `.dmg` 与 `.zip`。

- **未签名**:没有 Apple Developer ID,所以 Gatekeeper 会拦首启。选「**右键 → 打开**」确认一次即可,
  之后正常双击启动。不想每次都这样,终端执行一次:
  ```bash
  xattr -dr com.apple.quarantine /Applications/MemorySQL.app
  ```
- **本版只提供 Apple Silicon(`arm64`)安装包。Intel Mac(`x64`)暂时需要手动构建或等待后续版本。**
  原因是 GitHub 托管的 Intel macOS runner 长时间排不到队(实测排队 95 分钟仍未分配),
  与代码无关。**这不是架构限制**,后续版本会补上。

### 关于 macOS 自动更新:请留意这一条

macOS 的自动更新**只在这一版之后的升级**才生效(此前没有 macOS 版本,不存在从旧版升级的情况)。
本版发布的 `latest-mac.yml` **只包含 arm64 条目**,因此:

- **Apple Silicon**:正常自动更新
- **Intel Mac**:若你在本版之上尝试自动更新,会因清单里没有 x64 包而报错。
  **Intel Mac 用户请从 Release 页面手动下载安装包**,不要用应用内的更新按钮

等 x64 产物补齐后,清单会合并为同时包含两个架构,Intel 用户即可恢复正常自动更新。

## 修复

### OpenCode 的 MCP 配置自 v2 起一直写错(`type` 缺失被静默丢弃)

OpenCode ≥ 2.0 起 MCP server 条目必须带 `type` 字段,缺了会在配置规范化阶段被**静默丢弃**
(仅一条 WARN,不报错),症状是该 agent 的会话里 7 个 MCP 工具**整个不出现**。

`connectAgent` 写 `opencode.json` 时已补上 `type: remote`。

> **对存量用户尤其重要**:在你升级到本版之前,即使你重跑一遍连接向导,旧逻辑依然写不出
> `type`,MCP 一直是坏的。**装上这一版后请重跑一次「连接向导」**——只需一次,之后自动更新会
> 覆盖后续升级。用浏览器访问 `https://<你的MCP地址>/health` 也可确认服务在跑,
> 但工具出不来看的是 agent 侧的工具列表。

### 捕获失效不再静默:健康度三态 + 写后回读验证

之前捕获插件解析失败**只写一行日志**,`lastStatus` 不更新,界面上看不出任何差别。现在:

- 每个捕获插件有 `health` 状态(`正常` / `偶发` / `连续失败` / `未安装`),连续失败 3 次才升级为红色
- 设置页三态显示:**没装**(灰)、**正常**(绿)、**读不懂**(红)
  —— 这两者的处置方式完全相反:「没装」不用管,「读不懂」说明上游格式变了,要改适配器
- 修掉 4 处 watcher 失败只写日志的地方(通用工厂、Codex、ZCode、Hermes)
  ——其中 Hermes 那处最隐蔽:失败发生在 `scan` 内部,`scan` 之后仍然报成功,连 `lastError` 都没有
- `connectAgent` 写完 MCP 配置后**回读校验**,失败会明确报「已写入但校验不通过」,
  而不是让你下次发现工具不见了

## 隐私与安全披露

新增 [`PRIVACY.md`](https://github.com/Logic647/MemorySQL/blob/main/PRIVACY.md),
把会碰到你敏感数据的地方逐条写清楚:本机明文保存什么、什么会离开机器、
文件夹同步的明文风险,以及**本机 MCP 端点是无鉴权的**这一事实与对应的信任假设。

> 简单说:所有内容都存在你自己机器上,项目**没有任何遥测**。
> 但请注意:本机会开一个**无鉴权**的本地 MCP 端点(仅绑 `127.0.0.1`),
> **本机上任何进程都能读取你的全部记忆与会话**。详见披露文档。
