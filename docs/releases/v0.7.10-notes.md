# MemorySQL v0.7.10 更新日志(2026-11-28)

> 修复:**macOS 安装后双击提示「已损坏,应移到废纸篓」**(Apple Silicon 实测),
> 且系统不给「仍要打开」入口。本版对 `.app` 补做完整的 ad-hoc 签名,
> 用户只需在「系统设置 → 隐私与安全性」点一次「仍要打开」即可。

---

## 修复:macOS「已损坏无法打开」

**原因**:此前 macOS 包完全没有签名(`mac.identity: null` + CI 关闭证书自动发现)。
产物里缺 `_CodeSignature`,但内部 Electron 可执行文件仍带编译期的残缺 adhoc 头 →
`codesign --verify` 报「code has no resources but signature indicates they must be present」。
macOS 15+/Apple Silicon 会把「浏览器下载的 quarantine 标记 + 残缺签名」判定为
**文件已损坏/被篡改**,而不是「未认证开发者」,因此连
「系统设置 → 隐私与安全性 → 仍要打开」的按钮都不出现。

**修复**:打包阶段新增 ad-hoc 签名步骤(仍不需要 Apple 开发者账号):

- 清掉打包产物的扩展属性,逐个签名 `app.asar.unpacked` 里的原生二进制
  (better-sqlite3、sqlite-vec 的 `vec0.dylib`),再对整个 `.app` 做深度签名;
- 签完立即执行 `codesign --verify --deep --strict` 严格校验,**校验不通过就让构建失败**
  —— 残缺包不会再发出去;
- 刻意不启用 Hardened Runtime(否则动态加载 `vec0.dylib` 与下载的语义组件会被拦)。

**表现变化**:双击安装包里的应用不再出现「已损坏」;首次启动会提示
「Apple 无法验证“MemorySQL”是否包含恶意软件」——点「完成」,然后到
**系统设置 → 隐私与安全性**,底部点「**仍要打开**」确认一次,之后正常双击启动。
终端快捷方式仍然可用:

```bash
xattr -dr com.apple.quarantine /Applications/MemorySQL.app
```

## 其他

- README 的 macOS 说明已同步更新(删掉了新版 macOS 已移除的「右键 → 打开」);
- `docs/RELEASE.md` 补充:将来接入 Apple Developer ID 转正式签名时,
  开 `hardenedRuntime: true` 必须同时提供含 `allow-jit` /
  `allow-unsigned-executable-memory` / `disable-library-validation` 的
  entitlements,否则同样会在加载原生模块时闪退。

## 升级

- Windows / Linux 安装包与自动更新链路同往常;macOS 双架构(dmg + zip)与
  合并后的更新清单一起发布,arm64 / Intel 都能自动更新到本版。
- 从 v0.7.9 升级的用户不受影响;只有首次在 mac 上安装 0.7.10 及以后版本的用户
  会用到新的签名。
