# MemorySQL v0.7.3 更新日志(2026-11-07)

> 这一版解决一个核心问题:**agent 不再等你开口才用记忆**。协议层 + 规则层双管齐下,让 agent 在你没说"续接"的时候也会主动查记忆、记决策、做收工汇报。

---

## 本次更新内容

### 1. MCP 主动调用(协议层,覆盖所有兼容 agent)

- MCP `initialize` 现在返回 **`instructions`**:写清四个调用时机——开工前查上下文(每会话最多一次)、答历史先搜索、拍决策立即写、收工必汇报——外加预算约束(不刷屏、不外传)
- 8 个 `memory_*` 工具的描述统一改为以**「【何时调用】」**开头:模型是照着描述决定要不要调的,以前只写"这是什么",现在写明"什么时候该用"
- 零配置,所有走 MCP 的 agent 立即生效;有测试锁住,新增工具漏写触发说明会红

### 2. 「写入规则」:把工作协议放进 agent 自己读的文件(第二层)

规则文件每一轮都会进上下文,比工具描述更硬。**13 家 agent 认哪个规则文件,全部经过测定**(金丝雀黑盒实测 / 开源源码 / 官方文档 / 资源翻查 / 同族推断,五级证据,台账可查):

- 设置 → 会话捕获 → 连接 Agent 向导,每行新增 **「写入规则」**:往该 agent 认的规则文件里追加一段带标记的工作协议
- 幂等(重复写只更新)、可逆(整块删除即还原,写前自动备份)、防腐(文件里已有没配对的标记时拒绝写入)
- 用户级规则(codex/claudecode/kimi/dsh 等)留空目录即全局生效;项目级规则(qoder 的 `.qoder/rules/`、codebuddy 的 `CODEBUDDY.md` 等)填项目根目录
- qoder 是规则**目录**:写入 `.qoder/rules/memorysql.md`,你自己的规则文件原样保留

### 3. 归档会话跟随源库(opencode 2.2.6 `--archived`)

opencode 2.2.6 起允许 `opencode run --archived` 把脚本化/CI 会话直接建成归档态。现在**跟随源的语义**:

- 归档会话照常入库、可全文检索,但会话列表默认不显示(「显示已归档」开关可见)
- 语义单调:源里的归档会同步进来;取消归档只由你在 MemorySQL 里决定,重扫不会翻回去

### 4. dsh 真机校准修正

真机(桌面版 2.0.22-next / 会话格式 v4)核对源码推导的 19 种事件全部吻合,并抓出一处行为差异:同一会话的 `session/title` 会落多次(用户第一句 → 模型总结 → 手动改名),旧实现取第一次,库里永远显示原始提问——**改为最后一次生效**。

### 5. 上游监控增强(看板 / NAS 面板 / 探针)

- **版本缺口标注**:黑盒 🟢 但数据早于上游最新发布时,标注「仅覆盖旧版本」而不是静默绿灯
- **白盒失明必须长红脸**:GitHub token 失效/大面积抓取失败不再被摘要写成"无风险"
- **gemini 检查修正**:json 源检查曾经无条件判绿(等于没查)
- **NAS 探针改 systemd timer**:开机补跑,不再因关机错过
- 看板与 NAS 面板新增「规则」行:该 agent 认哪个规则文件 + 证据等级,随 `git pull` 自动跟上
- 新增 `scripts/rules-probe.mjs` 金丝雀探测工具(沙箱种 11 个候选规则文件 + 唯一暗号,行为直接给答案)

## 升级说明

Windows / Linux / macOS(arm64 + Intel)均已发布,自动更新静默收取。**macOS 仍未签名**,首次启动需「右键 → 打开」。

让 agent 真正"主动"起来还差最后一步:**升级后在设置 → 会话捕获 → 连接 Agent 向导里,给你常用的 agent 点一下「写入规则」**(用户级的留空目录即可)。云看板 / NAS 面板的服务端部署:`git pull` 后重启对应进程即可。
