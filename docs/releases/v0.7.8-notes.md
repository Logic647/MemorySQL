# MemorySQL v0.7.8 更新日志(2026-11-20)

> 修复:**刚开始对话就触发项目总结、同一场对话被切成多条总结**;
> 修复:项目记忆整理常驻「上次失败」(LLM 超时 / 输出无法解析);
> 导出/导入提示改为自动消失。

---

## 修复:一聊天就开始总结

- **不再总结正在写入的会话**:项目总结只消化「已经安静下来」的会话 ——
  自动触发等满设置的安静期(默认 30 分钟),手动「立即总结」也留 2 分钟宽限。
  你正在聊的这一场不会被拉进去。
- **同一场对话不会被反复总结**:一次总结触发内已处理过的会话不再回读;
  多轮消化只负责覆盖更多不同会话,不会追着不断新增消息的活会话一轮轮重跑。
- **LLM 失败不再逐轮等超时**:一次触发内 LLM 失败后,剩余批次直接走本地规则,
  不会再出现「总结中」持续十几分钟。
- **启动补跑避开活跃项目**:应用启动后的自动补跑会跳过安静期内仍有会话写入的项目;
  项目记忆的后台整理同样跳过 10 分钟内还在写的项目,交给下一次总结完成后再整理。

## 修复:项目记忆「上次失败」

- **超时从 45 秒放宽到 120 秒**:项目总结/记忆整理的输入较大,免费与本地模型
  (反代)经常 45 秒跑不完;超时/网络类错误还会自动重试一次。
- **模型不按 JSON 输出时**:
  - 回复「没有需要变更的记忆」这类话术 → 按「无变更」正常结束,不再记失败;
  - 其它非 JSON 输出 → 用「只输出 JSON」的严格提示再问一次;
  - 仍失败才记录错误,并在设置页显示模型输出的开头,便于定位。
- **token 预算上调**(项目 3000→5000、全局 2400→3500),推理型模型的思考
  token 不会再把 JSON 截断。
- **失败项目自动重试**:「立即整理全部项目」和下次启动补跑都会重试上次失败的
  项目(即使总结没有变化),旧的「上次失败」不会一直挂着。

## 体验

- **导出/导入提示自动消失**:导出备份后的「已导出 … 已打开备份文件夹」等提示
  6 秒后自动清除,不再常驻侧栏底部。

## 升级

- 更新包从 **GitHub Releases** 下载(`latest.yml` / `latest-mac.yml` / `latest-linux.yml`)。
- 升级不丢数据,无需手动迁移。
- 从 v0.7.5 起为「先问下载、下完再问安装」两步确认;下载完成后可立即重启安装,
  或稍后退出应用时自动安装。
