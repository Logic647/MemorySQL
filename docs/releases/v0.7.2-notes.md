# MemorySQL v0.7.2 更新日志(2026-11-06)

> 这一版是**看得见的两件事 + 感觉得到的四件事**:新增浅色主题,子代理会话不再挤占列表;底层把一堆卡顿从根上治了(搜索不再卡界面、长会话入库快 50 倍、启动扫描快 30 倍)。

---

## 本次更新内容

### 1. 浅色主题 + 双主题切换(新)

- 设置 → 通用 → **外观**:深色 / 浅色 / 跟随系统;顶栏右上角还有一键切换(太阳/月亮)
- 浅色不是深色反色:背景偏冷灰、面板近白、边框与文字重新定的对比度,**白底上的玻璃层次**重做过
- 切换对所有窗口立即生效(含 `Alt+Shift+M` 秒搜),窗口底色与 Windows 标题栏同步换色,不会闪一帧深色
- 顺手修掉一个一直存在的毛病:**设置页外围那圈黄色调试边框**(`TEMP DIAGNOSTIC` 残留)已删除

### 2. 子代理会话不再挤占列表(新)

过去 agent 派子代理,子代理会作为独立会话混进列表 —— 真机上 zcode 100 条里 **37 条**、opencode 36 条里 **5 条**都是这种「你是 xxx 子代理」的会话。

- 现在它们**照常入库、照常可搜**(内容不丢),但默认**折叠在父会话下面**:父会话下出现一条「↳ 7 个子代理会话 — 展开」
- 点开才按需加载,子会话行有缩进和紫色标记,详情页有「子代理」标签
- `memory_list_sessions` / `memory_get_context` / 项目总结**默认都不再被子代理刷屏**(需要时 `includeSubagents=true` 显式要)
- 会话列表 314 → **272 条**(本机实测),侧栏计数与列表口径一致

### 3. 语义检索不再阻塞界面(性能)

本地向量推理(fastembed / onnxruntime)从主进程搬进 **worker 线程**:

- 模型初始化 152ms、每次查询 24–33ms 全部移出主进程,搜索时 UI 与 MCP 请求不再卡顿
- 空闲 15 分钟自动释放,内存整块还给系统;worker 崩溃不影响主进程,自动降级纯全文检索

### 4. 长会话入库快 50 倍(性能)

会话内容变化时,过去是「删掉全部消息 + 全部全文索引再重插」。现在按消息序列只重写**变化的那段尾部**:

- 真会话(7,303 条 / 3.6MB)追加 1 条:**1,409ms → 28ms**
- 这也是「越用越卡」的主因之一:整会话重写会不断制造数据库空闲页

### 5. 启动更快(性能)

- 启动扫描推迟到窗口出来后、适配器之间让出事件循环(原来首屏要等 1.5s 的扫描块)
- 启动扫描改**水位增量**:只重读变化过的会话 —— zcode **809ms → 22ms**、opencode **640ms → 19ms**
- 插件的 watcher / MCP 监听 / 语义栈推迟到窗口创建之后(原来会挡 300–500ms)
- 会话列表从写死 200 条改成**分页加载**(此前超出部分在界面上根本不存在);渲染层产物再降 61%

### 6. 其他

- 设置页重命名输入不再每敲一个字就重渲染整个会话树
- 打开数据库时跑一次 `PRAGMA optimize`(此前从未 ANALYZE)
- `scoop` 清单修正并接入自动更新;`winget` 已收录

## 升级说明

Windows / Linux / macOS 均已发布,自动更新会静默收取本版。**macOS 仍未签名**,首次启动需「右键 → 打开」。

升级后第一次启动会做一次**全量重扫**(为了把历史会话的子代理标记补齐),大约多花几秒;之后恢复增量。
